# Telegram Desktop

Опциональный модуль позволяет включить локальный MTProto-прокси и его автозапуск через то же `service.bat`, которым управляется Zapret. Готовый Release содержит `bin/telegram/zapret-telegram.exe` со встроенным Python-рантаймом; пользователю не нужно устанавливать Python или вводить параметры прокси.

## Включение

1. Установите Telegram Desktop и распакуйте готовый Release в постоянную папку.
2. Запустите `service.bat`, выберите **9. Telegram**, затем **1. Enable and connect Telegram**.
3. После запуска прокси готовая ссылка откроет Telegram Desktop; подтвердите **«Подключить»**. Пункт **2. Connect Telegram** повторно открывает эту ссылку.
4. Проверьте отправку и получение сообщений, фото, видео и файлов, затем восстановление соединения после повторного входа в Windows.

При первом включении используется порт `1443`, а если он занят — выбирается свободный локальный порт. Порт и созданный secret сохраняются в `runtime/telegram/<SID>/config.json` для следующих запусков; `<SID>` — идентификатор текущего пользователя Windows. Если впоследствии сохранённый порт заняла другая программа, запуск сообщит о конфликте; существующие параметры прокси автоматически не меняются. Прокси слушает только `127.0.0.1`; другим устройствам в сети он недоступен.

Для автозапуска создаётся задание Планировщика Windows для текущего пользователя. Оно запускается при входе в Windows без повышенных прав. Telegram-прокси и служба `winws2` включаются и отключаются независимо друг от друга. Запуск модуля не меняет системный прокси, файл `hosts` или внутренние файлы Telegram (`tdata`).

Если при запросе прав Windows введены данные другого администратора, модуль всё равно привязывается к пользователю текущего рабочего стола и открывает Telegram от его имени.

После перезагрузки автозапуск происходит при входе пользователя в Windows. Это запускает только прокси; автозапуск самого приложения Telegram настраивается отдельно в Telegram. Если папку сборки переместили, сначала выполните **4. Disable proxy** из прежней папки, затем **1. Enable and connect Telegram** из новой.

## Как проходит соединение

```text
Telegram Desktop
  → локальный MTProto-прокси на 127.0.0.1
  → WebSocket поверх TLS
  → сервер Telegram
```

Модуль определяет дата-центр из начального MTProto-пакета и пробует WebSocket-маршруты, используемые Telegram Web. Передаются уже зашифрованные данные Telegram. Это изменение транспорта может помочь, когда обычное подключение Desktop фильтруется иначе, чем WebSocket/TLS.

Прямой WebSocket-маршрут идёт на серверы Telegram. По умолчанию также разрешены резервные маршруты через Cloudflare; список резервных доменов может загружаться автоматически. При таком fallback трафик проходит через инфраструктуру Cloudflare. Поэтому модуль не обещает, что каждое соединение будет идти напрямую на сервер Telegram. При необходимости ядро также пробует прямой TCP-маршрут.

Для любого маршрута нужна доступность соответствующего внешнего IP и TCP-порта. Если провайдер блокирует все доступные маршруты, преобразование в WebSocket само по себе соединение не восстановит. Исходящие TLS-соединения прокси могут попадать под текущие фильтры `winws2`; совместимость проверяется с выбранной стратегией и конкретным провайдером.

Модуль предназначен для Telegram Desktop на этом компьютере. Работу звонков и других способов передачи медиаданных проверяйте отдельно: исправные сообщения и WebSocket-соединение не подтверждают двусторонний звук или видео в звонке.

## Статус и диагностика

Основное меню `service.bat` показывает локальный статус Telegram. **Check Status** и **Run Diagnostics** также показывают состояние модуля без внешних сетевых проверок.

Пункт **Diagnose** в меню Telegram выполняет отдельную проверку прокси и доступности внешних маршрутов. Результат помогает отделить локальную проблему запуска от недоступного сетевого пути. Успешная проверка endpoint не гарантирует вход в конкретный аккаунт, загрузку медиа или работу звонков — это проверяется в приложении вручную.

Если Telegram не подключается:

1. Проверьте статус через **9. Telegram** и выполните **Diagnose**.
2. Повторите **Connect** и убедитесь, что в Telegram выбран именно локальный прокси этой сборки.
3. Проверьте, что сборка находится в той же папке, где выполняли **Enable**.
4. Сравните работу с установленной стратегией Zapret и с остановленной службой `winws2`.
5. Откройте лог по пути из **Show status** (`runtime/telegram/<SID>/proxy.log`). Secret скрывается при логировании; перед публикацией фрагментов также проверьте имена пользователя, локальные пути и сведения о соединениях.

Если отсутствует `zapret-telegram.exe`, скачайте полный Release ZIP. Автоматический GitHub Source code ZIP содержит исходники и не является готовой сборкой.

## Отключение и обновление

Выберите **9. Telegram → 4. Disable proxy**. Модуль остановит свой процесс и удалит своё задание автозапуска. Затем в Telegram откройте **Настройки → Продвинутые настройки → Тип соединения** и отключите этот прокси. Название раздела может отличаться в зависимости от версии приложения.

Настройки внутри Telegram автоматически не меняются. Если приложение продолжает использовать остановленный локальный прокси, соединение через него работать не будет. Локальный config сохраняется, чтобы при повторном включении в той же папке использовать прежний secret.

При обновлении в новую папку:

1. Выполните **Disable** в старом `service.bat` и отключите старый локальный прокси в Telegram.
2. Распакуйте новый Release ZIP в новую постоянную папку.
3. Выполните **Enable → Connect** в новом `service.bat` и подтвердите подключение.

Не включайте `runtime/telegram` в публичные архивы: каталог содержит локальные настройки и secret. Настройки каждого пользователя находятся в подкаталоге с его Windows SID. В Release эти данные не включаются.

## Исходники и сборка компонента

Используется закреплённое ядро `tg-ws-proxy` v1.11.1, commit `18175fb4fe567cf6aef61f9d883eff010c9e66a8`. Исходники находятся в `third_party/tg-ws-proxy`; сведения об авторстве и лицензии — в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md), исходный текст MIT — в `third_party/tg-ws-proxy/LICENSE`.

Для разработчиков в исходном репозитории:

```powershell
python -m pip install -r packaging/telegram-requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File utils/build-telegram.ps1 -Python "C:\path\to\python.exe"
```

Используйте один и тот же Python для установки зависимостей и сборки. Сценарий создаёт фоновый EXE в `bin/telegram/zapret-telegram.exe`; обычному пользователю эти команды не нужны. В GitHub Actions компонент собирается на Windows с Python 3.12 x64. Release упаковывает EXE и пользовательские скрипты управления, а исходники и инструменты сборки остаются в репозитории.
