# Обновление с сохранением настроек

Откройте `service.bat`. Проверка стабильного релиза выполняется в фоне: меню доступно сразу. Если появилась надпись **«Доступна новая версия … Чтобы обновить Zapret, введите 111»**, введите **111** и нажмите Enter. Пункт **12. Check for Updates** повторяет проверку вручную; пункт **6. Auto-Update Check** включает и выключает автоматическую проверку.

Обновляется сама сборка Zapret 2 NEXT из настроенного репозитория, а не отдельный движок из upstream. Beta, alpha, rc, черновики и более старые версии не предлагаются.

## Что происходит

1. Проверяется доступность GitHub; архив и его SHA256 полностью скачиваются, пока старая версия продолжает работать.
2. Проверяются архив, компоненты и возможность перенести прежнюю конфигурацию. При ошибке подготовки программа остаётся на старой версии.
3. Меню закрывается, отдельное окно обновлятора заменяет файлы сборки в той же папке и восстанавливает прежнее состояние запуска.
4. После успешного запуска старые файлы удаляются, открывается новое меню. Если замена или запуск не удались, возвращается старая версия.

Длительность скачивания зависит от соединения. Во время подготовки Zapret работает; после начала замены сеть временно может стать недоступной. Повторная загрузка с GitHub на этом этапе уже не нужна.

Перед заменой файлов обновлятор также останавливает WinDivert, если драйвер зарегистрирован из этой папки. При запуске движок загружает его снова. Это освобождает старый `WinDivert64.sys` для удаления резервной копии; драйвер из другой папки обновлятор не останавливает.

## Что сохраняется

- Стратегия, Game Filter и его диапазоны TCP/UDP, IPSet Filter, Discord Voice, оба UDP Fake и состояние автоматической проверки.
- Выбранные пользовательские UDP-фейки в `lists/fakes` с проверкой SHA256.
- Все текущие файлы в `lists`, включая основные списки, личные списки и загруженный IPSet. Новые отсутствующие файлы добавляются из релиза.
- Весь `runtime`: история диагностики, логи и настройки Telegram с прежними портами, secret и правами доступа.
- Состояние службы, ручного запуска и Telegram. Работавшие компоненты запускаются снова; остановленные не включаются автоматически. Если службы не было, обновление её не устанавливает.

Применённый конфиг и отложенные настройки меню сохраняются отдельно. Если вы изменили переключатель, но отказались перезапускать службу, обновление не применит это изменение за вас.

Основные списки сохраняются по выбору пользователя: их содержимое не заменяется новыми списками релиза. Для отдельного обновления IPSet по-прежнему используйте пункт 10.

Локальные пресеты и их лаунчеры нужно сохранить отдельно: папки `presets` и `strategies` заменяются файлами релиза. Если служба использует локальный пресет, сначала выберите штатную стратегию через **1. Install Service**, выполните обновление и верните свои файлы в новую версию.

## Если обновление остановилось

При недоступном GitHub, повреждённом архиве, нехватке места, чужой службе, неизвестном ручном запуске или неподдерживаемой стратегии обновление сообщает причину. Ручные изменения сгенерированного активного конфига автоматически не переносятся. Установка из Git checkout через этот механизм не обновляется.

Ошибка `0xC0000142` (`-1073741502`) при проверке `winws2` означает сбой инициализации DLL до чтения конфигурации. Проверочный запуск повторяется до трёх раз в пределах общего тайм-аута. Обновление продолжается только после успешной проверки конфигурации; если ошибка остаётся, подготовка прерывается до остановки работающих компонентов и замены файлов.

После принудительного закрытия обновлятора или выключения компьютера снова откройте `service.bat`: сначала выполнится восстановление незавершённой замены. Журнал находится в `runtime/release-update/transaction.json`. Если автоматическое восстановление не удалось, резервная копия остаётся в указанном там `session-…/backup`; не удаляйте её до восстановления.

Если новая версия уже работает, но удалению старых файлов мешает другая программа, обновление считается успешным. Очистка повторится при следующем запуске меню.

## Переход со старой сборки

Опубликованная 0.4.1 и более ранние версии требуют одного ручного обновления: удалите прежнюю службу, отключите Telegram-модуль, распакуйте актуальный релиз в отдельную папку и настройте запуск из неё. Сохраните прежнюю папку, пока не перенесёте свои списки и нужные настройки; не копируйте старый `runtime` целиком поверх новой установки. Начиная с 0.4.2 следующие стабильные версии можно устанавливать через **111**.

## Если обновление не удалось

В окне показаны причина, код `UpdateFailed` и состояние восстановления. Создайте архив через **13. Run Diagnostics → 5. Create logs archive** и приложите ZIP к обращению. Подготовка, HTTP/curl-коды, повторные загрузки, проверки, замена файлов, откат и очистка связаны одной сессией; журнал остаётся в `runtime` при обновлении и восстановлении. Значения секретов, пользовательские списки и необработанные сообщения команд в архив не включаются. Подробнее: [отчёты и логи](SUPPORT.md).
